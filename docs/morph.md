# 轮廓过渡形变

设计师在两枚轮廓之间生成一系列过渡稿。入口 `POST /v1/plates/{id}/morph`：

```json
{
  "from_revision": 1, "from_shape": "lobe-a",
  "to_revision": 2, "to_shape": "lobe-a",
  "steps": 4, "expected_revision": 2
}
```

成功时 201 返回 `{plate, morph}`：`steps` 个过渡稿在一次原子提交中追加为普通稿本（上例为稿本3..6），与手写稿本一样可以继续 PUT 修订、渲染 PNG/SVG、封包移交。`expected_revision` 与修订入口语义相同，过期即 409。任何失败都不追加稿本。

## 对应与重采样方法

输入两稿可以有不同起点、相反绕向和不同数量的控制点，按以下固定顺序处理：

1. **包含树分类**：轮廓按点包含关系建树，深度偶数为外边界、奇数为镂空。分类只看几何，不信任输入绕向。镂空只与同一外层下的镂空配对，数量不一致直接说明，绝不把镂空接到外边界上。
2. **绕向归一**：外边界统一为正面积、镂空为负面积，输出稿本用 nonzero 填充规则表达同一拓扑；相反绕向的输入在此被消化。
3. **弧长均匀重采样**：每对环重采样到相同顶点数 N（24..96，受单形状 256 操作预算约束，超预算按比例下调但不低于 12），消除控制点数量差异。
4. **起点对齐**：方向由填充语义固定，只搜索循环平移，取对应顶点平方距离和最小者，吸收不同起点。
5. **逐顶点线性插值**：t = i/(steps+1)，在版面坐标中进行（两端各自 transform 已应用），输出稿本的 transform 为单位矩阵。两端笔刷都是实色时颜色随 t 线性混合，否则沿用起始稿笔刷。
6. **可信门槛**：源稿、目标稿和每个中间帧都检查——环不自交、环间不相交、镂空保持在其容器内。任一帧失败则整个请求以 400 说明拒绝，不输出自交乱线，也不留下半截序列。

无法建立可信对应时给出说明而不是图形：外边界数量不同、同一外层下镂空数量不同、退化（近零面积）轮廓、源稿或目标稿自身不可信、中间帧自交或镂空逃逸。响应 `morph` 字段报告每环的角色/顶点数/平移量/对应距离，以及每帧的面积/周长/自交数/镂空包含标志。

## 如何判断过渡质量（非对称示例）

examples/morph-lobe.json（起点稿）与 examples/morph-lobe-rev2.json（目标稿）是一枚喙部在右上、镂空偏左的非对称瓣形：两稿起点不同、绕向相反、控制点数量不同（C 曲线对 Q 曲线加五边形镂空）、镂空位置移动。用非对称图形是因为对称轮廓会掩盖对应错误——旋转对称的环在错误的平移对齐下看起来仍然正常，而非对称喙部让错位立刻可见。

判断依据，先看报告再看图：

- **对应距离**：`rings[].mean_distance` 与 `max_distance` 应同量级。max 远大于 mean 说明局部特征被拉错位，应调整两稿的特征分布再试。示例外环为 9.0/14.7，镂空为 15.9/18.4，属均匀对应。
- **面积与周长曲线**：`frames[].area`、`perimeter` 应平滑漂移（示例面积 9208→8596→8000→7419 单调收敛到目标）。中途凹陷或尖峰意味着对应错误或插值经过退化形态。
- **结构标志**：`self_intersections` 必须恒为 0，`holes_contained` 必须恒为 true；服务已把违反者挡在门外，报告里看到即确认。
- **目视**：渲染中间稿（t=0.4、0.6），喙部应连续移动而不是消失后在别处重生，镂空始终是镂空。对称图形看不出"喙部跑到另一侧"这类错误，非对称图形一眼可辨。

形变是确定性的：同一对稿本在同一服务版本下重放得到相同稿本摘要，walkthrough 的 morph 流程用独立版面重放并比对摘要验证这一点。

## 边界

单对形状之间的形变；多外边界需两侧数量一致并按质心贪心配对。中间帧与所有稿本一样走同一编译准入（操作数、画布、渲染预算），超预算场景以既有错误文本拒绝。插值不发明拓扑：镂空数量不变的配对才成立，需要分裂/合并镂空的过渡应拆成多次形变。

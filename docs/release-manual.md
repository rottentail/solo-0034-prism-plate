# 棱版版本放行手册

本手册供维护者在拿到旧、新两份发布材料时照章执行，判定三种处置：**保持已签成品的原引用**、**只需重新出图**、**通知接收方重新验样**。配套演练：`python3 scripts/release_rehearsal.py`（第 5 节）。

## 0. 原则

- 放行决定只依据可复核证据：实际成品字节、解码后的完整像素矩阵、源稿摘要、矢量校样字节、可重出性探针结果、校样终局状态。
- 禁止仅凭文件摘要、文件大小、修改时间或缩略图做放行决定。摘要相同不等于源稿相同（采样盲区，见 4.2）；摘要不同不等于内容不同（编码差异，见 4.1）。
- 三个标识语义不同，务必区分（实现见 internal/service/service.go、internal/transport/http.go）：
  - **成品 id**＝Hash(版面:稿本号:稿本摘要:格式:内容摘要)，是谱系标识。源稿任何变化都产生新 id，即使成品字节完全相同。
  - **成品摘要 / ETag**＝成品字节的 SHA-256，是字节标识。编码器或压缩策略变化会产生新摘要，而解码像素可以不变。
  - **X-Scene-Digest / revisions[n].digest**＝源稿摘要，是源稿标识。渲染、成品响应头与版面历史中均可取得。

## 1. 发布材料清单

旧包（上一版已放行）：

- 已签成品 id 与字节：`GET /v1/artifacts/{id}`，同时记录响应头 `ETag` 与 `X-Scene-Digest`。
- 该成品上已 accepted 的校样 id。
- 版面稿本历史：`GET /v1/plates/{id}`，记录各稿本 `digest`。
- 同稿本的 SVG 成品字节（几何见证基线）。

新包（候选）：

- 候选源稿（或稿本号）、候选成品字节或重新出图结果。
- 若发布涉及服务本身（渲染器、编码器、准入规则、持久化格式），需候选构建与旧数据根的启动验证。

## 2. 判据与执行

| 判据 | 执行 | 结论语义 |
|---|---|---|
| C1 源稿一致性 | 比较新旧 `X-Scene-Digest` / 稿本 `digest` | 同＝源稿未变；不同＝谱系已变 |
| C2 字节一致性 | 对成品字节计算 SHA-256，与 ETag 对比 | 只证明字节，不证明内容 |
| C3 像素一致性 | 用解码器把两份 PNG **完整解码**为像素矩阵，逐通道全量比对（宽×高×通道），报告最大通道差 | 一致＝视觉内容相同。禁止抽样、禁止缩略图 |
| C4 几何见证 | 比较同稿本 SVG 成品字节，或对源稿 JSON 做结构化 diff | SVG 与光栅共用同一展开几何，是采样盲区的见证 |
| C5 可重出性探针 | 对旧稿本 `POST /v1/plates/{id}/render?revision=N&format=png` | 201＝可重出；400＝该源稿在当前准入下不可重出。每次发布前必测，不得假设 |
| C6 校样终局 | `DELETE /v1/artifacts/{id}` 对已 accepted 校样引用的成品返回 409 | 已签成品受系统保护，不可撤销、不可再激活 |

C3 的解码器不限实现；演练脚本内置一个仅依赖 Python 标准库的解码器（`png_decode`），保证流程自包含、可复核。

## 3. 放行判定

逐行核对决策表，取第一个匹配行：

| # | C1 源稿 | C3 像素 | C5 可重出 | 判定 | 接收方动作 |
|---|---|---|---|---|---|
| 1 | 同 | 一致（字节亦同） | 可 | **处置一**：保持已签成品的原引用（无变化） | 无 |
| 2 | 同 | 一致（字节不同） | 可 | **处置一**：保持原引用；若发布载体必须更新字节，退而**处置二**：只需重新出图，并在发布记录登记新旧成品 id 与字节摘要的映射 | 无 |
| 3 | 同 | 不一致 | 可 | **处置三**：同一源稿渲染结果发生变化，通知重新验样 | 必须重新验样 |
| 4 | 不同 | 一致 | 可 | **处置三**：采样盲几何变更（见 4.2），通知重新验样 | 必须重新验样 |
| 5 | 不同 | 不一致 | 可 | **处置三**：可见变更，通知重新验样 | 必须重新验样 |
| 6 | 同 | — | 不可 | **处置一（终局化）**：已签成品作为该源稿的最终发布保持原引用，标记"不可重出"；此后任何新图必须走新源稿，即转入**处置三** | 需要新图时必须重新验样 |

三种处置的定义：

- **处置一 保持已签成品的原引用**：继续以旧成品 id 及其摘要为发布引用，已签校样继续有效，不重新出图、不打扰接收方。
- **处置二 只需重新出图**：同一源稿重新出图即可发布。新成品 id 不同（内容摘要变了），但 C3 已证明像素一致，校样随内容继续覆盖；不通知接收方验样。
- **处置三 通知接收方重新验样**：以候选源稿出图、开新校样；接收方验样裁决通过之前，不得替换已签引用，不得撤销旧成品（C6 也会在系统层面阻止撤销）。

## 4. 三种易误判变化的机理与正解

### 4.1 PNG 字节变、解码像素不变（编码差异）

- 机理：PNG 编码器、压缩级别或过滤策略变化 → 字节与摘要变，解码像素不变。
- 误判：看 SHA-256 变了就要求重新验样（过度）；或看尺寸没变就直接替换引用（不足——未验证像素）。
- 正解：C3 全像素矩阵比对一致 → 决策表第 2 行。

### 4.2 细边几何变、当前 PNG 未采到（采样盲区）

- 机理：PNG 为每像素 2×2 定点覆盖采样，采样点固定在 x+0.25 / x+0.75 等位置（internal/raster/raster.go）。亚采样宽度的细边、或小于采样间隔的几何位移，可以完全不被采到：PNG 字节逐位相同，但 SVG（同一展开几何）必然不同。
- 误判：PNG 摘要相同 → "无变化"放行。
- 正解：C1 源稿摘要不同即触发**处置三**；C4 的 SVG 差异是几何变更的实证。PNG 像素一致**不能**作为免验证据——它只证明当前采样点没采到差别。

### 4.3 旧校样可下载、源稿不可重出（准入规则收紧）

- 机理：成品字节是持久化事实，已签校样阻止撤销；但渲染路径每次都以当前准入规则重新编译源稿（internal/service/service.go）。准入收紧后，旧源稿出图返回 400，旧成品照样可下载。
- 误判：能下载就以为可复现、可重出、可无限期作为现役引用。
- 正解：C5 探针实测；不可重出的已签成品按决策表第 6 行终局化。
- **发布硬检查**：服务启动时会重编译全部持久化稿本（cmd/prismplate/main.go）。收紧准入规则的版本必须自带旧数据祖荫或迁移策略，否则服务根本无法在旧数据根上启动。任何准入变更的发布候选，必须先在演练中验证"旧数据根可启动＋旧成品可下载＋旧源稿重出被拒"三件事。
- **移交注意**：封包只含稿本，不含成品与校样。跨站点移交时，已签成品字节必须随封包一并移交，否则接收方在新准入下无法复现旧图。

## 5. 演练

```sh
python3 scripts/release_rehearsal.py
```

需要 Go 工具链与 Python 3 均在 PATH；演练在临时目录构建真实服务，不修改仓库与演示输入。流程：

- **第 0 阶段（旧发布）**：用 examples/amber-proof.json 建版面，出 PNG/SVG 成品并下载字节，开校样并 accepted；验证已签成品不可撤销（409），同一源稿同一渲染器重出得到同一成品 id。
- **case-a**：用内置解码器解码已签 PNG，以不同压缩策略重编码得到新字节；断言字节与摘要不同、解码像素矩阵完全一致（最大通道差 0）→ 处置一（如需新字节则处置二）。
- **case-b**：追加稿本 2，在 cyan-glaze 层加入宽 0.25、落在采样点之间的细边形状；断言 PNG 字节逐位相同、成品 id 不同、SVG 字节不同、源稿摘要不同 → 处置三。
- **case-c**：关停旧服务；把源码复制到临时目录，收紧准入（画布上限 128）并给启动重编译加祖荫日志，构建模拟的"下一版"；在同一数据根启动；断言旧成品可下载且字节一致、两个旧稿本重出均 400、已签成品撤销仍被 409 拒绝、历史可读、启动日志含祖荫记录；再以合规新源稿（128×96）追加稿本 3 并成功出图，演示出路 → 处置一（终局化）＋ 出路必经处置三。
- **输出**：一份 JSON 证据报告，每个 case 带证据（摘要、最大通道差、状态码、错误文本）与 verdict；全部断言成立时退出码 0，任一失败即非零退出并指明失败点。

以下发布前必须跑演练：渲染/合成/采样变更、PNG 编码或工具链升级、准入规则变更、持久化格式变更。

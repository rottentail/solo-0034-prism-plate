# 采证与比对方法

本文说明这套演练怎样取证、怎样比对、能排除什么、以及哪些歧义无法用现有材料消除。文中结论都由 `tools/compare.py` 与 `tools/tamper_probe.py` 的实测输出支撑，可重跑核对。

## 一、采证：先固定“事实层”，再派生“接收层”

1. **在真实服务上执行**。`tools/build_drill.py` 启动一个临时数据根上的棱版服务，用公开 HTTP 契约提交场景、追加稿本、渲染 PNG/SVG、开立并裁决校样、导出封包。没有手绘像素，也没有绕过校验直接写快照。
2. **逐条录制**。请求与响应原文写入 `origin/transcript.jsonl`；二进制成品单独存放并以摘要引用；持久化快照原样复制为 `origin/state.json`。
3. **复算而不是相信**。对每个稿本独立重算与 Go `json.Marshal` 等价的场景摘要，必须与服务的 `digest` / `X-Scene-Digest` 一致；对每个成品重算字节摘要与“版面:稿本:scene_digest:格式:字节摘要”的成品 id，必须与响应一致。任何一项不符就中止构建。
4. **从同一批事实派生接收包**。`kit/` 只保留部分源稿、部分成品、部分响应；省略项在 `source_excerpt.omitted_revision_numbers` 与 `responses.withheld` 中登记，且**不携带被省略稿本的任何文本**。
5. **答案与材料物理分离**。`answer/` 记录样本出处与逐例论证；`kit/` 内不含答案标记，`tools/verify.py` 会检查。

采证只回答“服务当时产出了什么”，不回答“谁有权签样”。后者需要交接记录或签名，本服务不提供。

## 二、比对：从强证据到弱证据

按证据强度排序，前一级不能通过才降级到下一级：

1. **字节同一性**：接收样本与某成品字节完全相同（sha256 一致）。这是最强的同等性证据，但只在“样本就是该成品”时成立。
2. **成品 id 与场景摘要**：用公开字段复算 `sha256(plate:revision:scene_digest:format:byte_digest)`。它证明元数据自洽，不证明作者身份。
3. **全分辨率逐像素比对**：解码为 RGBA8 后逐像素比较，记录差异像素数、包围盒、最大通道差。这是排除候选的主要手段。
4. **缩略图比对**：只作筛查。4× 缩略图会把 1–2 像素的局部差异平均掉；本演练的丁案就是“缩略图相同、全分辨率差 2 像素”。
5. **SVG 对照**：SVG 是矢量校样，浏览器覆盖率与透明渐变插值可能与 PNG 不同，不作为逐像素认定依据。

编码副本（如 RGBA8 重编码）与源成品**像素相同、字节不同**。处理规则是：先验证派生记录中的“像素一致”是否属实，再用像素级证据；派生记录本身不带签名，因此不能单独用来认定来源。

## 三、三级结论的判定规则

`tools/compare.py bind` 的规则是显式的：

- **足以认定（`provenance_established`）** 同时满足：
  1. 已接受校样把某个成品 id 绑定到接收样本；
  2. 接收样本与该成品字节相同；
  3. 接收包内同版面其余稿本的成品都与样本存在非零像素差；
  4. 接收包声明本版面没有省略稿本。
- **只能列候选（`candidates_only`）**：像素能匹配，但缺少上述任一条件——最常见的是有省略稿本，或缺少校样/元数据绑定。
- **无法判断（`indeterminate`）**：包内没有匹配候选，且缺证无法闭合。

未纳入的稿本单独放在 `withheld_unresolved`，**不混进已匹配候选**。这是刻意的：它们既不是“已匹配”，也不是“已排除”。

## 四、这套方法能排除哪些候选

以实测数据为准（差异值见 `answer/arguments/*.md`）：

| 情形 | 能否排除 | 依据 |
|---|---|---|
| 可见标记改色 | 能 | 全分辨率差异成片出现（如甲案 144 像素、丙案 1152 像素） |
| 相邻 1×1 色标换位 | 能 | 全分辨率差 2 像素，包围盒 `[60,40,61,40]`；缩略图相同不能作为依据 |
| 被不透明遮片完全覆盖的改色 | **不能** | 像素与字节都与原稿相同 |
| `alpha=0` 图层任意改色 | **不能** | 合成结果不变，字节相同 |
| 带记录的编码副本 | 能绑定到源成品 | 像素一致 + 派生记录 + 成品元数据复算 |
| 另一版面产生的同像素图 | **不能**仅凭像素排除 | 丁案外部重渲染图与样本字节都相同，但没有谱系绑定 |
| 未纳入接收包的稿本 | **不能判断** | 没有可比对的成品，只能登记为不可排除 |

## 五、缺少什么证据会留下不可消除的歧义

1. **没有签名或交接记录**。校样裁决、派生记录与清单都在接收包内，可被整体重写。`tools/tamper_probe.py` 的 `forge_image_and_proof` 探针把图与校样一起改成自洽版本，工具会接受——这是不可消除的歧义，不是实现缺陷。
2. **成品字节相同但来源不同**。乙案 R1 与 R3 的成品字节完全相同，`scene_digest` 不同；像素与字节证据都无法区分，只能靠校样或交接记录。
3. **省略稿本**。只要真实版面还有未纳入的稿本，就不能宣称“足以认定”，因为未纳入稿本可能像素相同。工具因此把有省略的甲类情形降为候选。
4. **同像素的外部重渲染**。丁案证明“像素唯一性”本身不成立；认定只能到“样本属于被接受的该成品”，不能到“只有它能产生这些像素”。
5. **缺受签样本的源稿与元数据**。戊案只能排除 R1，无法给出候选，正确结论是“无法判断”。

## 六、怎样复核

```sh
# 全量重建并自检
python3 tools/build_drill.py --binary /tmp/prismplate

# 回执、结论、答案隔离
python3 tools/verify.py

# 反事实探针：哪些篡改会被抓到，哪些不会
python3 tools/tamper_probe.py --case kit/case-a
python3 tools/tamper_probe.py --case kit/case-c
```

`tamper_probe.py` 的预期结果本身就是教学点：`swap_image_only`、`pixel_edit`、`derivation_lie` 应被识别为包内不一致；`forge_image_and_proof` 预期**测不出**，因为接收包里没有能覆盖校样与清单的签名。

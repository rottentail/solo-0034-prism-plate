# 棱版坐标排错手册（制稿人员用）

本手册配合 `manual/` 下的 16 个可重跑小稿使用，解决一个具体问题：**镜像（或任何仿射调整）之后，校样上有东西偏了，怎么判断偏的是图案、跟随图案的渐变，还是仍在画布原处的裁域/二值蒙版。**

读完后你应当能：

1. 说清四类对象（形状路径、笔刷渐变、裁域 `clip`、二值蒙版 `mask`）各自在哪套坐标里；
2. 按小稿示范的方法选观察点，用源稿坐标核对 PNG 上看到的颜色；
3. 知道哪些错误在一张小 PNG 上**根本无法区分**，必须改观察点或看 SVG 几何；
4. 知道 PNG 在什么情况下无法反推源稿边界，下一步该去查哪里。

## 1. 四套对象、两套坐标

坐标原点在画布左上角，x 向右、y 向下，单位与 PNG 像素一一对应（画布最大 512×512）。源稿里每个对象只属于下面两套坐标之一，这是本手册全部判断的依据。

| 对象 | 源稿字段 | 所在坐标系 | 镜像时该不该动 | 渲染代码依据 |
|---|---|---|---|---|
| 形状轮廓 | `layers[].shapes[].path` | **形状局部坐标**，经 `transform` 映射到画布 | 动。改 `transform` 即可 | `raster.go` 先 `q = inverse(transform)(p)` 再判包含 |
| 渐变轴与停点 | `shapes[].brush.from/to/stops` | 同为形状局部坐标，在逆变换后的 `q` 处采样 | **自动跟随形状，不需要手工对停点** | `paint.Sample(brush, q)`，收到的是局部点 `q` |
| 裁域 | `layers[].clip` | **画布坐标**，直接对画布点 `p` 判定，无任何变换 | 不动。它是版面级约束 | `raster.go` 用原始 `p` 调 `Clip.Contains` |
| 二值蒙版 | `layers[].mask` | **画布坐标**，与裁域同一套判定 | 不动 | `raster.go` 用原始 `p` 调 `Mask.Contains` |

三条必须背下来的结论：

1. **裁域和蒙版不认识 `transform`。** 给形状加镜像矩阵不会把裁域/蒙版一起带走，这是正确行为而不是 bug。
2. **渐变没有自己的"位置"。** 它的轴写在局部坐标里，形状挪到哪里、翻成什么朝向，渐变就跟着在哪里、什么朝向。在 SVG 里表现为渐变定义不变、只是形状的 `transform` 变了（见案例02 的 SVG 对照）。
3. **镜像只需改形状的 `transform`。** 绕竖线 x = a 做水平镜像的矩阵是 `[-1, 0, 0, 1, 2a, 0]`。本手册案例04 的画布宽 64、绕 x = 32 镜像，平移项就是 64。手工对调渐变停点属于二次反转，是典型错误（案例04 错误乙）。

## 2. 渲染器怎么看一个像素：观察点为什么有效

PNG 渲染对每个像素做 **2×2 四点覆盖采样**，四个采样点在像素内的位置是 (x+0.25, y+0.25)、(x+0.75, y+0.25)、(x+0.25, y+0.75)、(x+0.75, y+0.75)，四点结果取平均（`internal/raster/raster.go`）。

由此得到三条排错时直接用得上的分辨率事实：

- **整数网格线**（如 x = 32）正好穿过采样点之间：边界落在这里时，一边四点全在内、另一边四点全在外，得到干净硬边，不产生半透明像素。
- **半像素线**（如 x = 32.5）穿过一列像素的中线：该列两个采样点在内、两个在外，得到 50% 覆盖的混合像素。
- **落在两个采样点之间、又没跨到另一侧采样点的边界移动，PNG 完全看不见。** 采样点间距只有 0.5 像素，所以小于半个像素、且不跨过任何采样点的边界移动会被整张 PNG 吞掉。案例03 演示的就是这一点。

**观察点**是写在每个小稿 `probes` 里的整数像素坐标，配合 `manual/tools/probe.py` 可以直接读出该像素的实测 RGBA8。本手册所有表格里的数值都是渲染器实际产出、由 `outputs/manifest.json` 登记的值，不是手算估计。颜色约定：背景色统一为 sRGB (0.04, 0.055, 0.09)，编码后是 **RGB(10, 14, 23)**；橙实色 (0.95, 0.45, 0.12) 编码后是 **RGB(242, 115, 31)**。

## 4. 案例01：实色下，形状错放与蒙版错放的小 PNG 不可分

### 4.1 版面与两版错误

- 画布 64×64；二值蒙版是矩形 **x∈[16,48]、y∈[16,48]**。
- 实色方块局部轮廓 **x∈[16,40]、y∈[24,48]**。基准稿 `transform` 为单位阵，画在画布原处。
- **错误甲 `c01-shape-shift`**：方块 `transform` 改成 `[1,0,0,1,16,0]`（右移 16），蒙版不动。方块画布落点变为 x∈[32,56]。
- **错误乙 `c01-mask-shift`**：方块不动，蒙版轮廓改成 x∈[32,64]（右移 16）。

### 4.2 为什么只看一张小 PNG 分不出来

两版错误真正出颜色的区域（"蒙版内 ∩ 形状内"）分别是 [32,48]（错误甲）和 [32,40]（错误乙），它们的**公共上色条带是 x∈[32,40]、y∈[24,48]**。在公共条带内、以及下面三个常规观察点上，两版读数完全相同：

| 观察点 | 基准 c01-baseline | 错误甲 形状右移 | 错误乙 蒙版右移 |
|---|---|---|---|
| (20,32) | (242,115,31) 实色 | (10,14,23) 背景 | (10,14,23) 背景 |
| (36,32) | (242,115,31) 实色 | (242,115,31) 实色 | (242,115,31) 实色 |
| (54,32) | (10,14,23) 背景 | (10,14,23) 背景* | (10,14,23) 背景 |

\* 错误甲在 (54,32) 处方块其实存在（方块到 x=56），只是蒙版在 x=48 截止把它裁掉了——PNG 上同样只看到背景。**"看不见颜色"无法区分"那里本来没东西"和"有东西但被蒙版/裁域挡掉"。**

两版错误的 PNG 摘要不同（`db2d1674…` vs `608e993a…`），因为错误甲在独占区 x∈[40,48] 还有颜色、错误乙没有；但如果观察点只布在公共条带和背景区（这是只盯"色块本身"时最自然的布点方式），你拿到的读数两版一模一样，无法判断自己手上是哪一版。把点移到独占区就能分开，见下节。

### 4.3 分开方法一：换观察点到"独占区"

选一个**只有一方覆盖**的位置。方块右移后覆盖到 x∈[40,56]，而不动的方块只到 x = 40，于是 **x = 44 就是独占区观察点**：

| 观察点 (44,32) | 错误甲 形状右移 | 错误乙 蒙版右移 |
|---|---|---|
| 实测 RGBA8 | **(242,115,31) 实色**（在交集带 [32,40] 之外仍被形状覆盖，且蒙版到 x=48） | **(10,14,23) 背景**（蒙版新位覆盖到这里，但形状只到 x=40） |

同一点、同一背景、同一支笔刷，一个出颜色一个不出——这就把两类错误分开了。错误甲还可以在 (54,32) 旁证：蒙版在 x=48 截止，所以 (54,32) 仍是背景，说明**蒙版留在原处没跟着走**；错误乙在 (54,32) 同样是背景，但原因是形状没延伸过来，需要配合 (44,32) 才能归因。

### 4.4 分开方法二：看 SVG 几何

SVG 把两类对象放在不同元素里，一眼可分（`outputs/svg/c01-shape-shift.svg` 与 `c01-mask-shift.svg`）：

错误甲——蒙版几何是原处的 `M16 16…`，形状带着平移矩阵：

```xml
<clipPath id="m0" clipPathUnits="userSpaceOnUse">
  <path d="M16 16L48 16L48 48L16 48Z"/>
</clipPath>
...
<path d="M16 24L40 24L40 48L16 48Z" ... transform="matrix(1 0 0 1 16 0)"/>
```

错误乙——形状矩阵回到单位阵，蒙版几何变成 `M32 16…`：

```xml
<clipPath id="m0" clipPathUnits="userSpaceOnUse">
  <path d="M32 16L64 16L64 48L32 48Z"/>
</clipPath>
...
<path d="M16 24L40 24L40 48L16 48Z" ... transform="matrix(1 0 0 1 0 0)"/>
```

判读规则：**`clipPath` 里的路径永远是画布坐标原值；形状 `path` 是局部轮廓，真实位置要乘上 `transform`。** 看哪个元素的数字变了，就是哪个对象偏了。

## 5. 案例02：换一个观察点，或看 SVG 几何，就能分开两类错误

### 5.1 版面

与案例01 同构，但方块换成水平线性渐变：局部轴 `from=(16,0)` → `to=(48,0)`，暖端 (1.0,0.7,0.22) → 冷端 (0.1,0.45,0.95)。因为渐变在局部坐标采样，方块右移 16 后，**同一画布坐标读到的渐变参数 t 会整体平移**——渐变是跟随对象，这是正确行为。

### 5.2 同坐标读数对照

| 观察点 | 基准 c02-baseline | 错误甲 形状+渐变一起右移 | 错误乙 只移蒙版 |
|---|---|---|---|
| (20,32) | (239,171,111) 暖，t=0.125 | (10,14,23) 背景 | (10,14,23) 背景 |
| (36,32) | (163,142,201) 冷，t=0.625 | **(239,171,111) 暖，t=0.125** | **(163,142,201) 冷，t=0.625** |
| (44,32) | (10,14,23) 背景 | (205,158,164) 中间色，t=0.375 | (10,14,23) 背景 |
| (54,32) | (10,14,23) 背景 | (10,14,23) 背景 | (10,14,23) 背景 |

渐变比实色多给了一个免费的判据：**在两版错误都出颜色的 (36,32)，颜色本身就不同**。错误甲的渐变跟着方块走，x=36 落在新方块的 t=0.125 处，读出暖色 (239,171,111)；错误乙的渐变轴没动，x=36 仍是 t=0.625，读出冷色 (163,142,201)。实色案例01 在这个点两版同色，渐变案例02 不用换点就能分——但前提是你拿得到两版稿做对照；只有单张校样时，仍然要靠独占区 (44,32) 归因。

### 5.3 SVG 证据：渐变定义不动，动的是 transform

两版错误 SVG 里的 `<linearGradient>` 元素**逐字符相同**（`x1="16" x2="48"`，停点相同），差别仍只在蒙版路径与形状矩阵：

```xml
<!-- 两版共有的渐变定义：局部坐标，不随 transform 改变 -->
<linearGradient id="b0_0" gradientUnits="userSpaceOnUse" x1="16" y1="0" x2="48" y2="0">
  <stop offset="0" stop-color="rgb(100%,70%,22%)" .../>
  <stop offset="1" stop-color="rgb(10%,45%,95%)" .../>
</linearGradient>
```

所以排错时不要去渐变定义里找"渐变有没有偏"——**渐变永远写在局部坐标，它在画布上的位置由形状的 `transform` 唯一决定。** 看到渐变方向/位置不对，先查形状矩阵，再查停点是否被人手工改过（案例04 错误乙）。

## 6. 案例03：镂空压在像素边缘，PNG 不能断定源稿边界

### 6.1 三个稿本的差别只有一个数

形状是 evenodd 填充的外环（12,12)–(52,52) 挖一个内镂空，镂空左缘分别放在：

| 稿本 | 镂空左缘 | PNG sha256（前 12 位） |
|---|---|---|
| `c03-hole-edge320` | **x = 32.0**（正好整数网格线） | `6e7a7d3b6dd5` |
| `c03-hole-edge321` | **x = 32.1**（偏 0.1） | `6e7a7d3b6dd5`（**与上者完全相同**） |
| `c03-hole-edge325` | x = 32.5（像素中线，对照） | `c4e3186b1d45` |

前两张 PNG **逐字节相同**（完整摘要见 `outputs/manifest.json`），但源稿边界差了 0.1 个画布单位。

### 6.2 为什么 PNG 吞掉了这 0.1

x = 32 这条网格线两侧最近的采样点是 x = 31.75（像素 31 内）和 x = 32.25（像素 32 内）。边界从 32.0 挪到 32.1，两个采样点的内外归属都没变：31.75 仍在镂空外、32.25 仍在镂空内。整张图没有任何一个采样点易主，于是像素输出完全一致。

观察点实测（y=34 行）：

| 观察点 | 甲 x=32.0 | 乙 x=32.1 | 丙 x=32.5 |
|---|---|---|---|
| (31,34) | (242,115,31) 实色 | (242,115,31) 实色 | (242,115,31) 实色 |
| (32,34) | (10,14,23) 背景，四点全在镂空内 | (10,14,23) 背景，同上 | **(178,83,27) 半覆盖混合色** |
| (33,34) | (10,14,23) 背景 | (10,14,23) 背景 | (10,14,23) 背景 |

丙稿的边界压在像素 32 的中线上，该像素两个采样点在内、两个在外，橙色与背景按 50% 混合出 (178,83,27)——这是 PNG 能表达的最强边界信号。即便如此，它也只能告诉你"边界穿过了这个像素的中线附近"，**无法区分 32.4、32.5、32.6 这类落进同一像素覆盖区间的取值**。

### 6.3 排错结论与下一步

- **单靠 PNG 不能断定源稿边界。** 两张摘要相同的 PNG 可以对应不同的源稿几何；反过来，想确认镂空到底在 32.0 还是 32.1，像素证据不存在。
- 下一步查两处：
  1. **源稿 JSON** 的 `path` 顶点（本手册对照：32.0 写在 `c03-hole-edge320.json`，32.1 写在 `c03-hole-edge321.json`）；
  2. **SVG 几何**，两个 SVG 的 path 分别是 `…ZM32 24L48…` 与 `…ZM32.1 24L48…`，保留完整浮点精度，这是边界问题的权威矢量证据。
- 经验阈值：硬边两侧出现**完全不透明的跳变**，说明边界落在采样点之间（网格线附近 ±0.25 内都可能如此）；出现**半透明过渡像素**，说明边界穿过了某个像素内部。两种情况都不能把边界位置反推到优于 0.5 像素的精度。

## 7. 案例04：镜像综合演练与三种典型漏改

画布 64×64，形状是局部矩形 (16,20)–(48,44)，带与案例02 同向的暖→冷渐变。基准稿用矩阵 `[-1,0,0,1,64,0]` 绕 x=32 做水平镜像；裁域是**非对称**矩形 x∈[8,52]、y∈[12,52]（左留 8、右留 12，故意不对称，让裁域镜像能被看见）。

### 7.1 基准稿 c04-baseline：正确镜像长什么样

矩阵把局部点 (x,y) 映到 (64−x, y)：局部左缘 16 → 画布 48，局部右缘 48 → 画布 16，形状在画布上仍占 x∈[16,48]，但朝向翻转。渐变在局部采样，于是颜色方位也跟着翻：

| 观察点 | 实测 RGBA8 | 含义 |
|---|---|---|
| (8,32) | (10,14,23) | 裁域 x∈[8,52] 的边界上、形状外，背景 |
| (18,32) | **(83,121,234) 冷色** | 镜像形状左半，读到的是原局部右侧的冷端 |
| (32,32) | (191,152,179) | 中缝，渐变中段 |
| (46,32) | **(250,176,80) 暖色** | 镜像形状右半，读到原局部左侧的暖端 |
| (58,32) | (10,14,23) | 裁域外（裁域只到 x=52），背景 |

### 7.2 错误甲 c04-no-mirror：漏加镜像矩阵

`transform` 仍是单位阵，形状和渐变都保持原朝向。几何位置与基准重合（形状本身关于 x=32 对称），所以**轮廓位置看不出问题，错的只是朝向**：(18,32) 变成暖色 (246,175,92)、(46,32) 变成冷色 (67,119,237)，与基准正好对调。查 SVG 的 `transform` 是否还是 `matrix(1 0 0 1 0 0)` 即可确诊。

### 7.3 错误乙 c04-stops-reversed：几何镜像对了，停点被手工对调

矩阵正确（`matrix(-1 0 0 1 64 0)`），但两支停点颜色被人为交换，等于把渐变朝向**第二次反转**，画面与错误甲完全一致：

| 观察点 | 错误甲 漏镜像 | 错误乙 停点对调 |
|---|---|---|
| (18,32) | (246,175,92) 暖 | (246,175,92) 暖 |
| (46,32) | (67,119,237) 冷 | (67,119,237) 冷 |

两张 PNG 摘要相同（`edd41fb0…`），又是一对**单看 PNG 不可分**的错误。SVG 里它们的差别一目了然：错误甲是单位矩阵 + 原停点，错误乙是镜像矩阵 + 对调的停点。修复方式相反——甲要补矩阵，乙要把停点改回去。**记住第 1 节的规则：镜像只改 `transform`，停点不要动。**

### 7.4 错误丙 c04-clip-mirrored：裁域被一起镜像（PNG 完全无信号）

裁域关于 x=32 镜像后从 x∈[8,52] 变成 **x∈[12,56]**，形状矩阵保持正确。问题在于形状只覆盖 x∈[16,48]：两版裁域在形状覆盖区内都是"放行"的，而形状之外本来就没有颜色。于是：

- **两张 PNG 逐字节相同**（摘要同为 `e848b8c3…`），任何观察点都分不开；
- 观察点 (10,32)：基准在裁域内、错误丙在裁域外，但两点都没有形状覆盖，PNG 都是背景 (10,14,23)；
- 观察点 (54,32)：基准在裁域外、错误丙在裁域内，同样因为形状只到 x=48，PNG 还是背景。

这正是"仍在画布原处的裁域偏了、但 PNG 看不见"的典型情形。**唯一证据在 SVG**：

```xml
<!-- 基准：裁域留原处 -->
<clipPath id="c0" ...><path d="M8 12L52 12L52 52L8 52Z"/></clipPath>
<!-- 错误丙：裁域被镜像 -->
<clipPath id="c0" ...><path d="M12 12L56 12L56 52L12 52Z"/></clipPath>
```

排错规则：**凡是怀疑裁域/蒙版位置，但形状没有覆盖到差异区，PNG 必然给不出信号，直接查 SVG 的 `clipPath` 坐标或源稿的 `clip`/`mask` 字段。**

## 8. 案例05：screen 叠色与层透明度不改变结论

案例05 把案例01 的实色层换成 `blend: "screen"`、层透明度 0.72、笔刷 alpha 0.82（与 `examples/amber-proof.json` 的 cyan-glaze 层同款配置），验证混合模式不会改变坐标层面的结论。

- 错误甲（方块右移）与错误乙（蒙版右移）的交集带仍是 x∈[32,40]，该带内两版都是同一 screen 叠色 **(24,131,170)**；
- 独占区观察点 **(44,32)** 依旧一锤定音：错误甲有叠色 (24,131,170)，错误乙是背景 (10,14,23)；
- (20,32) 与 (54,32) 两版同为背景，不可分。

结论：**混合模式和透明度只改颜色怎么算，不改"谁覆盖谁"的几何判定。** 案例01/02 的全部观察点方法在 multiply/screen、部分透明度下原样适用。注意两版错误的 PNG 摘要不同（`bab84574…` vs `28e66129…`），不可分指的是"只有单张校样、或只盯交集带"时分不出归因，不是两张图字节相同。

## 9. 通用排错流程与观察点选择规则

### 9.1 拿到一张"镜像后偏了"的校样，按这个顺序走

1. **先归类对象。** 打开源稿，确认异常涉及的是 `shapes[].path/transform/brush`（局部坐标族）还是 `layers[].clip/mask`（画布坐标族）。
2. **形状族异常先查 `transform`。** 镜像矩阵应为 `[-1,0,0,1,2a,0]`（水平）或 `[1,0,0,-1,0,2a]`（垂直）。再确认没有人手改停点——渐变轴和停点应当与镜像前逐字相同。
3. **裁域/蒙版族异常直接查画布坐标原值。** 它们不随 transform 变化；如果稿子里给 clip/mask 套了变换思路，那就是错误本身。
4. **PNG 上选观察点取证**（规则见 9.2），用 `tools/probe.py` 读数，与本手册同类案例的表格对照。
5. **遇到三种"PNG 无信号"情形，转 SVG/源稿几何**：
   - 差异落在形状覆盖区之外（案例04 错误丙）；
   - 边界移动小于采样点间距、没有采样点易主（案例03）；
   - 两版错误的覆盖集合相同、只是成因不同（案例01 交集带、案例04 错误甲/乙）。
6. **归因后决定下一步检查哪里**：形状偏 → 查 transform 与提交稿本号；渐变朝向错 → 查停点有没有被二次编辑；裁域/蒙版偏 → 查版面级字段的修订记录；边界精度存疑 → 以 SVG path 数值为准，不要在 PNG 上量像素。

### 9.2 观察点选择规则

- **不要只在"出颜色的地方"布点。** 交集带内两类错误读数相同（案例01 的 x=36、案例05 的 x=36），那里是观察盲区。
- **把点布在独占区：** 只有形状覆盖、蒙版不覆盖的位置（验证蒙版留原处，如案例01 的 (54,32)），或只有蒙版/裁域覆盖、形状不覆盖的位置（验证形状留原处）。案例01/02/05 的关键区分点 x=44 就是按这个规则选的。
- **渐变稿优先在同坐标比颜色。** 跟随的渐变会让同一画布坐标的 t 值平移，颜色本身就是判据（案例02 的 (36,32) 暖/冷之分）。
- **边界问题沿垂直于边界的方向，在边界两侧各布一个整数像素点，再加一个中线点。** 硬跳变说明边界在采样点之间；半透明像素说明边界穿过像素内部；两种情况都给不出亚像素精度（案例03）。
- **每个观察点都要能在源稿里手算出预期。** 本手册所有点都选在 y=32/34 等横穿矩形内部的扫描线上，避开斜边与圆角，便于用区间包含手算。

### 9.3 不可分情形速查表

| 情形 | 为什么 PNG 分不出 | 分开手段 | 对应案例 |
|---|---|---|---|
| 形状右移 vs 蒙版右移（实色、单图） | 公共交集带内读数相同，常规观察点都落在盲区 | 独占区观察点 x=44；或 SVG 看是 matrix 变还是 clipPath 变 | 01、05 |
| 漏镜像 vs 停点对调 | 覆盖相同、渐变朝向结果相同 | SVG 比对 transform 与 stops | 04 甲/乙 |
| 裁域镜像到形状覆盖区之外 | 差异区本来就没有像素颜色 | 只能看 SVG `clipPath` / 源稿 clip | 04 丙 |
| 镂空边界 32.0 vs 32.1 | 没有采样点易主，PNG 逐字节相同 | 源稿顶点或 SVG path 数值 | 03 甲/乙 |
| 渐变稿两版错误（有双稿对照时） | — | 同坐标 (36,32) 比暖/冷即可，不必换点 | 02 |

## 10. 复现与校验

需要 Go 1.24+（渲染器）和 Python 3 标准库（探针与校验），无需网络、无需第三方包。

```sh
# 1. 从源稿重新生成全部 PNG/SVG 与 manifest（确定性输出，摘要应当不变）
go run ./manual/tools/rendercases ./manual

# 2. 全量校验：成品摘要、三对 PNG 等价对、四组区分点、全部探针
python3 manual/tools/check_manual.py            # 不重渲染，只校验现有 outputs
python3 manual/tools/check_manual.py --rerender # 先渲染再校验

# 3. 对单个小稿按源稿观察点读像素
python3 manual/tools/probe.py manual/sources/c01-shape-shift.json \
    manual/outputs/png/c01-shape-shift.png
```

`rendercases` 不启动 HTTP 服务，而是直接调用服务端同一套 `internal/validate`、`internal/raster`、`internal/vector` 包，因此它产出的 PNG/SVG 字节与 `POST /v1/plates/{id}/render` 的成品一致。想走真实 HTTP 路径复核时，把任一 `sources/*.json` 里的 `document` 作为版面 body 按 `README.md` 的启动步骤提交即可（注意补上顶层 `id`、`title`，这些字段在小稿里位于 document 之外）。

`check_manual.py` 的断言对应本手册的全部关键论点：

- 三对 PNG 等价对逐字节相同，且对应 SVG 必然不同（案例03 甲乙、案例04 基准/丙、案例04 甲/乙）；
- 四组区分点在同一观察点读出不同像素（案例01/02/05 的形状错放 vs 蒙版错放、案例03 的网格线 vs 中线）；
- `manifest.json` 登记的每个 sha256 与磁盘成品一致，每个探针实测值与 PNG 一致。

## 11. 术语速查

| 术语 | 含义 |
|---|---|
| 画布坐标 | 以 PNG 左上角为原点的坐标，clip/mask/背景使用 |
| 局部坐标 | 形状 `path` 与渐变轴使用的坐标，经 `transform` 才到画布 |
| 观察点 | 源稿 `probes` 中登记的整数像素坐标，用于在 PNG 上取证 |
| 独占区 | 只有形状或只有蒙版/裁域一方覆盖的区域，是归因两类错误的关键布点位置 |
| 交集带 | 形状与蒙版/裁域共同覆盖、真正产生颜色的区域；两类错放在此读数相同 |
| 四点采样 | 每像素在 (±0.25,±0.25) 处取四个覆盖样本再平均，决定 PNG 的几何分辨率 |
| 硬边 / 半覆盖像素 | 边界落在采样点之间产生不透明跳变；边界穿过像素内部产生半透明过渡 |
| 二次反转 | 镜像后又手工对调渐变停点，使渐变朝向被翻转两次的典型错误 |

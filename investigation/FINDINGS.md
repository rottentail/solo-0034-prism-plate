# 百万级仿射缩放下 SVG 几何退化调查报告

## 0. 一句话结论

问题不在稿本、也不在服务的 PNG 权威渲染，而在 **SVG 导出的数字序列化**：
`internal/vector` 用 `fmt.Sprintf("%.9g", x)`（`vector.go:12`）只保留 9 位有效数字。
当变换矩阵元素约为 1e6、轮廓坐标约为 3.2e5 时，9 位有效数字的舍入把矩阵的两个
本不相等元素写成相同值、把轮廓顶点写成对称整数，查看器按文件文本重算后两个顶点
**精确塌缩到原点 (0,0)**，四边形面积变为 **0**，只剩一条落在 y=x 对角线上的退化线。
PNG 走的是另一条逆变换采样路径，不做这次大数相减，因此几何完好。

## 1. 四个必须分开核对的层面

| 层面 | 数据来源 | 四个画布顶点（近似） | 多边形面积 |
|---|---|---|---|
| A. 原稿意图 | 提交值的十进制精确运算（Decimal，60 位） | (8,8) (40,8) (40,40) (8,40) | **1024.0003** |
| B. 服务计算几何 | IEEE binary64 前向求值（与 Go `Matrix.Apply` 同序） | 与 A 偏差 ≤1.6e-8 | **1024.0003** |
| C. SVG 文件实际文本 | 真实服务产出的 `repro.svg` | `matrix(1000000 1000000 1000000 1000000 0 0)` + `…L320000 -320000…` | — |
| D. 查看器重算几何 | 解析 C 的 token 后用 binary64 重算 | (8.00000271,8.00000271) **(0,0)** (40.0000135,40.0000135) **(0,0)** | **0** |

A/B/C/D 的逐项可复算对照见 `results/precision-layers.json`
（由 `scripts/precision_investigation.py` 生成）。

### 1.1 退化是怎么发生的（两层舍入叠加、误差互相放大）

1. **矩阵层**：提交的 m0=999999.9996、m2=999999.9995（本差 0.0001，行列式 det=100，
   完全合法可逆）。`%.9g` 在 1e6 量级的网格间距是 **0.01**，二者都落在
   [999999.9995, 1000000.0005) 舍入区间，全部写成 `1000000`。查看器看到的矩阵
   m0′=m2′，这一位置上的差分值变成 0，近奇异矩阵被文件**精确表达成奇异矩阵**。
2. **轮廓层**：319999.99988 / −319999.999872 在 3.2e5 量级（网格间距 0.001）
   分别被写成 `320000` / `-320000`，原本不严格对称的两个点被写成精确相反数。
3. **查看器求值**：x 分量 = 1e6·320000 + 1e6·(−320000)，binary64 下
   `3.2e11 + (−3.2e11)` 精确等于 **0.0**（不是接近 0，是恰好 0）。两个顶点因此
   精确落在 (0,0)，四点共线于 y=x。

误差放大倍率：矩阵 token 最大绝对误差 5e-4（`precision-layers.json` 中
`max_abs_matrix_token_error`），乘上 3.2e5 的轮廓坐标 → 画布上单项误差可达
**约 160 px**；轮廓 token 误差 1.68e-4 乘 1e6 缩放 → 同样可达 **约 168 px**。
最终结果取决于这些大误差项是否恰好对消，不能只看某一张截图。

### 1.2 为什么 PNG 不受影响

`raster.go:37-38` 对每个像素中心做**逆变换** `s.Inverse.Apply(p)` 再在局部空间做
包含测试，从不执行“大数相乘再相减”的前向求值。该矩阵行列式 binary64 下恰好为
100.0，逆矩阵元素仅 1e4 量级（`precision-layers.json` 的 `png_inverse_pipeline`），
数值稳定。实测真实服务 PNG：**1024 个完全不透明蓝色像素，覆盖 bbox x[8..39]
y[8..39]，即完整的 32×32 四边形**（`results/degenerate-quad-repro/png-coverage.txt`），
与原稿意图一致；重复渲染摘要相同，确定性也成立。

### 1.3 查看环境本身的附加不确定性

用 `scripts/svg_viewer_check.py` 按 SVG 文本重算，面积为 0、四点共线；但同一退化
多边形在逐像素中心采样下仍点亮 **(13,13)、(27,27) 两个像素**，nonzero 与 evenodd
结果相同——因为退化对角线恰好穿过这两个采样点。真实浏览器带抗锯齿时，通常会沿
y=x 画出一条若有若无的细斜线。即“退化成线”之后还会因查看器栅格化规则不同而出现
零星、不可在产品间复现的像素。环境内无浏览器/rsvg，结论基于对文件文本的确定性
几何重算（任何 binary64 SVG 引擎的顶点求值都与此一致）。

## 2. 真实服务验证（HTTP，非模拟）

服务由本仓库 `cmd/prismplate` 构建，四份稿本均经 `POST /v1/plates` +
`POST .../render?format=png|svg` 真实渲染并下载成品
（`scripts/verify_on_service.py`，元数据与摘要存
`results/service-verification.json`）：

| 稿本 | 变换要点 | 真实 PNG | 真实 SVG 查看器面积 |
|---|---|---|---|
| `quad-degenerate-repro`（题面原案） | det=100，四元素同舍入到 1e6 | 1024 px 完整方块，bbox 8..39 | **0**（四点共线，仅 2 个偶发像素） |
| `quad-degenerate-neighbor` | m2=1000000，det=**−400**（反射，仍合法） | 1192 实色+48 半透明像素 | **0**（同样塌缩） |
| `quad-control-noncolliding` | m2=999999.9994，token 不碰撞（…999 vs 1000000） | 1464 像素、溢出到画布边缘 | 10240（**比意图大 10 倍**，顶点被甩到 ±320） |
| `quad-workaround-baked` | 坐标预烘焙到画布空间 + 单位矩阵 | 1024 px，bbox 8..39 | 1024.0003，与 PNG 一致 |

对照案证明：同网格内即使没有完全塌缩，也会产生量级错误（面积 10×、顶点漂移
~56.6 px，见 `results/perturbation-sweep.csv` 的 `same_grid` 段），问题不限于
题面这一组数字。

## 3. 影响范围：哪些“仍合法”的变换受影响

准入规则（`validate.go:147-160`、`geom.go:17-23`）只检查有限性、行列式绝对值
≥1e-10、逆矩阵元素有限，**完全不感知序列化精度**。探针
（`investigation/probe`，直接调用真实 `validate.Compile` 与 `vector.Export`）
结果存 `results/perturbation-sweep.csv` 与 `results/rounding-boundaries.txt`。

### 3.1 完全塌缩（查看器面积 = 0）的合法区间

以 m0=m1=m3=999999.9996 为例，`%.9g` 与 m0 撞成同一 token 的 m2 区间由二分实测：

- 下界 m2 ≥ **999999.9995**（含；999999.99949 仍写为 999999.999，不碰撞）
- 上界 m2 ≤ **1000000.005**（不含；1e6 量级网格间距 0.01，半宽 0.005，
  再加 m0 自身距 1e6 的 0.0004）

即 |m2−m0| 在约 **1e-4 到 5.4e-3** 内、且 m2 跨过 1e6 舍入边界的合法矩阵都会让
查看器矩阵在该位置变奇异。已实测的塌缩合法点：m2=999999.9995（det=100）与
m2=1000000（det=−400）。均匀矩阵 `[s,s,s,s]` 本身 det=0，会被准入器以
`singular transform` 拒绝，不在受影响集合内。

另外注意准入器 `finite()`（`validate.go:15`）规定所有输入绝对值 ≤1e6，
因此 1000000.0001 及以上的矩阵元素直接以 `invalid transform` 被拒——受影响
区间的上界同时被这条容量规则封死，风险窗口集中在 ~3.2e5 到 1e6 这一段。

### 3.2 同网格但不塌缩：仍有画布级错误

所有元素落在同一 0.01 宽舍入网格（约 [999999.9995, 1000000.0005)）的可逆矩阵，
即使 token 不完全相同，顶点最大漂移也达 **40.8–56.6 px**（48×48 画布上即整幅
画布尺度）。面积误差则随行列式变化：m2 扫描 d=−0.0001 行服务面积 2048、查看器
10240（**5× 服务、10× 意图**，对应 HTTP 对照案 `quad-control-noncolliding`，
其顶点被甩到 ±320、bbox 撑满画布宽度）；而 `same_grid` gap=0.001 行面积恰好
守恒（服务与查看器都是 10240）但顶点仍整体漂移 56.6 px——即不塌缩不等于
正确，网格内任何构造都带着数十 px 的系统性顶点错位。

### 3.3 量级门槛

`%.9g` 网格间距随量级放大：1e5 量级为 0.001、1e6 量级为 0.01
（`rounding-boundaries.txt` 第 1 节）。固定 1e-4 元素差的量级扫描显示，
**s≈316227.766（即 1e5.5）起查看器面积已为 0**，s=999999 与 s=1000000 全部塌缩；
s≤1e5 时漂移 ≤5.7 px 且不退化。通用判据：当 `元素量级 × 元素相对差` 小于该量级的
半个舍入网格（即 `|Δm|/|m| ≲ 5e-10`，9 位有效数字的分辨率）时，两个元素在文件中
不可区分；再叠加轮廓坐标的同类舍入，就可能产生精确对消。任何约 ≥3.2e5 量级、
条件数高到依赖元素间 1e-9 级相对差表达的可逆变换都在风险区。

### 3.4 不受影响的部分

- PNG 成品（逆变换路径，见 1.2），以及引用 PNG 的校样、摘要与持久化谱系。
- 变换与轮廓坐标都在小量级（≲1e5 且元素相对差 ≫ 5e-10）的稿本。
- 渐变轴、颜色、裁域/蒙版：颜色经百分比 `%.9g` 输出但数值在 0..100，
  不会触发大数对消；画布坐标（≤512）的裁域/蒙版同样安全。
- 但已用真实 `vector.Export` 证实：若给**图层裁域/蒙版**喂入大坐标轮廓，
  `vector.go:39,42` 用的是同一个 `path()` 与同一个 `number()`，319999.99988
  同样被写成 `320000`（探针临时验证后已删除，未保留 HTTP 稿本），存在同型
  缺陷；蒙版/裁域的舍入不会与大变换相乘（它们直接处于版面坐标），但仍会
  产生亚千分之一量级的轮廓偏移。

## 5. 结论可信度标注

**有直接证据支持：**
- 9 位有效数字序列化是退化的直接原因（真实 SVG 文本 + token 重算面积 0）。
- PNG 与 SVG 几何分歧，PNG 符合原稿意图（真实成品像素统计 vs SVG 重算）。
- 查看器侧 (0,0) 是 binary64 精确对消而非近似误差（重算值恰为 0.0）。
- det=100 与 det=−400 两个合法变换均塌缩；同网格非碰撞矩阵存在 10×/数十 px 错误。
- 塌缩碰撞边界 999999.9995 与 1000000.005 由二分实测。
- 准入器拒绝真正奇异/病态矩阵，但对序列化导致的“文件侧奇异”无防护。

**推断、未在本环境直接验证：**
- 真实浏览器抗锯齿下的具体细线外观（环境无浏览器；仅能证明顶点共线、面积 0，
  以及逐采样点规则下的 2 个偶发像素）。
- 蒙版同型缺陷仅验证了序列化行为，未构造完整 HTTP 稿本核对其栅格化后果。

## 6. 作者临时规避方法

1. **首选：把变换预烘焙进轮廓坐标**，在创作侧用全精度算出画布空间顶点（本题即
   约 (8,8)/(40,8)/(40,40)/(8,40)），提交单位变换。已验证
   `quad-workaround-baked.json` 的 PNG 与 SVG 面积均为 1024.0003、覆盖完全一致。
2. 避免让变换元素进入 ~1e6 量级：把缩放因子降到 1e5 以下（同形状按比例放大局部
   坐标即可），使 `%.9g` 的 0.001 网格不再吞掉元素间差异。
3. 避免元素相对差 ≤5e-10 的近奇异构造；若业务上必须保留近奇异矩阵，先在创作侧
   烘焙，不要把“大数 × 大坐标再对消”的表达留给 SVG 查看器。
4. 移交时以 PNG 校样为视觉权威（README 已声明 PNG 是像素校样权威结果），
   SVG 仅作复用参考；对必须保真的矢量稿，在接收方用本报告的查看器重算方法
   核对面积/包围盒后再入库。

服务侧的根治方向（本次仅记录、未改产品代码）：导出前将仿射变换烘焙进路径顶点
再输出（与 PNG 共用同一份编译几何），或把数字格式提升到 17 位有效数字
（`%.17g` 可往返 binary64），并在准入器增加“序列化后矩阵不得奇异/条件数不得越界”
的校验，让 HTTP 入口与持久化恢复入口走同一约束。

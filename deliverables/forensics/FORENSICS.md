# 棱版合成配方鉴别手册

面向接收旧 PNG 图稿的同事。目标问题：一张图上看到的色差，究竟来自**色刷颜色**、
**整层/笔刷透明度**，还是**混合方式（normal / multiply / screen）**？单张背景上的
结果可以有多种解释，本手册用棱版**现有能力**构造可追溯的候选稿，先展示确实难以区分
的观测，再用额外背景与半透明探针把能区分的候选分开，并明确给出增加观测后**仍无法
唯一确定**的情形。所有结论都落在 8 位 PNG 量化误差给出的**候选区间**上，而不是猜
一个答案。

本材料不新增任何生产求解接口：全部图像都经由既有的
`POST /v1/plates`、`PUT /v1/plates/{id}`、`POST .../render`、`GET /v1/artifacts/{id}`
产生，分析脚本只读取服务已经导出的 PNG 与稿本摘要。

## 1. 合成模型（推导所用的等式）

棱版在**线性光、预乘 alpha** 空间合成（`internal/paint/paint.go`、
`internal/raster/raster.go`），只在导出 PNG 时转成 8 位 sRGB。对一个全覆盖的实色
图层，记：

- sRGB 色刷颜色经 sRGB 传递函数后的**线性**直通色为 s（每通道一个值）；
- 笔刷 alpha 为 a_b，整层不透明度为 o_l；
- 有效源覆盖度 **o = a_b · o_l**（`raster.go` 对预乘像素整体 `Scale(Layer.Opacity)`）；
- 背景线性直通色为 d（不透明背景时 dst.A=1）。

三种被准入的混合方式，在不透明背景上的逐通道输出 y 为：

| 混合方式 | 线性光输出等式 | 只依赖的复合量 |
|---|---|---|
| normal | `y = (1−o)d + o·s` | o 与 s（两个独立量） |
| multiply | `y = d·[1 − o(1−s)] = d + o·d·(s−1)` | **k_m = o(1−s)** |
| screen | `y = d + o·s(1−d)` | **k_s = o·s** |

关键事实（由等式直接读出，决定了后面所有可辨识性）：

1. normal 一条等式里有 o、s 两个未知数，单个 d 只能约束它们的一个线性组合。
2. multiply 在不透明背景上只通过 `o(1−s)` 出现；screen 只通过 `o·s` 出现。
   因而**任意多个不透明背景**都无法在这两个家族内部拆开 o 与 s。
3. 笔刷 alpha 与整层不透明度在整条管线里**只以乘积 o = a_b·o_l 出现**，
   任何像素观测都不能把这两个因子分开——这是结构性的，不是采样不够。
4. 半透明背景（dst.A<1）会让输出 alpha 也携带信息（见 §4），这是唯一能直接
   观测覆盖度 o 的探针。

PNG 量化：导出码 `c = round(srgb(y)·255)`（Go 的 `math.Round`，半入）。一个观测码 c
对应的真实 sRGB 值是闭区间

```
Q(c) = [ (c−0.5)/255 , (c+0.5)/255 ]      （端点 0/255 处截断到 [0,1]）
```

因此反演必须传播这个区间，输出参数区间而非点值（脚本 `model.code_interval`）。

## 2. 观测方案：为什么能提供新信息，何时失效

### 2.1 方案内容

对同一份候选图层，在 8 个背景上各渲染一张 96×96 PNG（见 `recipes.BACKGROUNDS`）：

- 7 个**不透明**背景：中灰（原始单背景）、纯黑、纯白、橙色、深灰、浅灰、红；
- 1 个**半透明**探针 `bg-alpha50`：sRGB(0.5,0.5,0.5) 且背景 alpha=0.5。

探针几何是覆盖 `[4,92]²` 的实色矩形，内点区域 `[12,84]²` 在四点超采样下全部满覆盖，
排除了覆盖率/抗锯齿混淆，使每个内点只反映“颜色 × 透明度 × 混合方式”。

### 2.2 为什么每个背景都带来新信息

- **换不透明背景值 d**：normal 的 y 对 d 有斜率 `(1−o)`，而两个不透明候选若 o 不同，
  斜率就不同，于是第二、第三个 d 能把 normal 家族里共用一个线性组合的候选分开。
  对 multiply/screen，换 d 不改变 `o(1−s)`、`o·s` 的可见性，所以不透明背景**对这两个
  家族内部无效**——这本身就是一条可证伪的结论，而不是遗漏。
- **纯黑 / 纯白端点**：multiply 在黑上恒为黑、screen 在白上恒为白（与参数无关），
  用来识别混合方式；normal 在端点上仍保留颜色信息，行为不同，故可区分混合模式。
- **彩色背景（橙、红）**：逐通道独立，提供与灰阶不同的 d，能暴露中性色假设不成立的
  候选，并交叉验证灰阶结论。
- **半透明探针 bg-alpha50**：这是覆盖度的直接观测。dst.A=0.5 时输出直通 alpha 为
  `a_out = o + 0.5(1−o) = 0.5 + 0.5o`，与混合方式、颜色都无关，于是
  **o = 2·a_out − 1**。它把 multiply/screen 在不透明背景上的退化族拆开。

### 2.3 何时失效（必须向同事讲清的边界）

- **multiply/screen 的不透明背景**：无论加多少个，族内都不可拆（等式只含复合量）。
  本材料用 B、C 家族在全部 7 个不透明背景上逐码相同来实证这一点。
- **半透明探针也只能到乘积 o**：`o = a_b·o_l` 的两个因子仍不可分。B2（笔刷
  alpha=1、层不透明度=0.75）与 B4（笔刷 alpha=0.75、层不透明度=1）在**全部 8 个背景**
  上逐码相同，包括半透明探针——这是增加观测后仍无法唯一确定的硬例子。
- **零覆盖家族 D**：零不透明度图层与画在画布外的轮廓，任何背景都只看到裸背景，
  颜色/透明度/混合方式全部不可辨识。
- **量化盲区**：若两个候选的连续输出都落在同一个 `Q(c)` 内，8 位 PNG 无法区分；
  区间反演给的是“仍相容的参数范围”，范围宽度就是这次观测的真实分辨力。
- **几何前提**：结论建立在满覆盖内点上。若原图只有边缘抗锯齿像素或渐变，超采样平均
  会把覆盖率与颜色混在一起，需要先取得满覆盖区域，否则区间要额外并入覆盖不确定度。

## 3. 候选家族与“先难后分”的实证

16 个候选稿、6 个家族，参数全部是棱版合法输入（单位区间、三种准入混合、闭合轮廓、
可逆/单位变换）。每个候选在每个背景上都是一个独立稿本，谱系见
`render-manifest.json`。等终局目标（中灰背景上的 8 位码）：

| 家族 | 混合 | 候选 | 中灰上的目标码 | 单背景能否区分 |
|---|---|---|---|---|
| A | normal | A1 不透明 / A2 o=0.70 / A3 o=0.50 | (115,153,189) | 否，三者同码 |
| B | multiply | B1 o=1 / B2 o=0.75 / B3 o=0.55 / B4 笔刷alpha=0.75 | 灰 96 | 否，四者同码 |
| C | screen | C1 o=1 / C2 o=0.70 / C3 o=0.50 | 灰 186 | 否，三者同码 |
| EM | normal vs multiply | EM1 / EM2 | (71,87,107) | 否，两者同码 |
| ES | normal vs screen | ES1 / ES2 | (158,179,204) | 否，两者同码 |
| D | 无覆盖 | D1 零不透明度 / D2 画布外轮廓 | 裸背景码 | 否，两者同码 |

### 3.1 家族 A（normal）：单背景难分，第二个背景立刻分开

中灰上三者同码 `(115,153,189)`。换成黑背景，输出分别是
`(115,153,189)`、`(92,138,178)`、`(71,127,170)`——因为 normal 对 d 的斜率是 `(1−o)`，
o 不同斜率就不同。**任何一个额外不透明背景都足以把 A 全部分开。**

### 3.2 家族 B（multiply）与 C（screen）：不透明背景全部失效，半透明探针才分开

B 的四个候选在**全部 7 个不透明背景**（含彩色橙、红）上逐码相同，因为它们共享
`k_m = o(1−s)`；C 同理共享 `k_s = o·s`。到 bg-alpha50，输出 alpha 码分别为
255 / 223 / 198（B）与 255 / 217 / 191（C），覆盖度被直接读出，族内据此分开。
但 B2 与 B4 的 alpha 码都是 223——见 §2.3 的永久歧义。

### 3.3 家族 EM / ES：混合方式本身的等终局

- EM：normal 深色与全强度 multiply 在中灰上同码 `(71,87,107)`。黑背景上 multiply
  必为黑 `(0,0,0)`，normal 保留 `(71,87,107)`，黑背景分开二者。
- ES：normal 浅色与全强度 screen 在中灰上同码 `(158,179,204)`。白背景上 screen 必为
  白 `(255,255,255)`，normal 保留 `(158,179,204)`，白背景分开二者。

这说明“混合方式”也不能从单背景像素唯一判定，必须借助端点背景的混合代数性质。

### 3.4 家族 D：增加观测后仍无法确定

D1（层不透明度 0）与 D2（轮廓在画布外）在 8 个背景上的每个像素码都相同，
bg-alpha50 上也同为裸背景 `(128,128,128,128)`。没有任何像素级观测能区分它们；
要区分只能回到稿本/几何来源，而不是看图。

完整逐背景码表与同/异判定由 `build_report.py` 写入 `appendix-tables.md`。

## 4. 哪些参数能被哪些观测约束（可辨识性推导）

设观测为若干背景 `{d_i}` 上的输出码，经 `Q(c)` 得到线性光区间 `Y_i`。

| 参数 | 单张不透明背景 | 多张不透明背景 | 加 bg-alpha50 探针 |
|---|---|---|---|
| normal 的 s 与 o | 仅约束 `y=(1−o)d+o·s` 一条线（一族解） | 两个不同 d 解出 o 与 s（量化区间内） | 直接得 o 区间，再由任一直线得 s 区间 |
| multiply 的 `o(1−s)` | 可定（一个复合量） | 不新增信息，仍只有复合量 | 得 o 区间，进而得 s 区间 |
| screen 的 `o·s` | 可定（一个复合量） | 不新增信息，仍只有复合量 | 得 o 区间，进而得 s 区间 |
| 有效覆盖度 o | 不透明背景 alpha 恒 255，**无信息** | 仍无信息 | `o=2·a_out−1`，直接量化区间 |
| 笔刷 alpha a_b 与层不透明度 o_l | 只可见乘积 o | 只可见乘积 o | **仍只可见乘积 o，永不因子化** |
| 混合方式（三选一） | 单背景可构造等终局，不可定 | 端点背景（黑/白）+ 彩色背景可定（除零覆盖 D） | 探针不直接判模式，但提供 o 后可反解验证 |
| 零覆盖 vs 画布外 | 不可定 | 不可定 | 不可定（家族 D，需稿本/几何来源） |

### 4.1 量化区间反演的具体形式

normal、不透明背景，已知假设的 o 时，色刷线性色区间为

```
s ∈ [ (min Y − (1−o)d)/o ,  (max Y − (1−o)d)/o ]  （截断到 [0,1]）
```

再经 sRGB 传递函数得到色刷 sRGB 区间。家族 A 的实测反演见附录 B.1：每个候选的声明
色值都落在自己的可接受区间内，且不同 o 假设给出**不同的 s 区间**——这正量化了“单
背景无法唯一确定”的含义：不是没有答案，而是一组随 o 变化的相容区间。

覆盖度反演（附录 B.2）：bg-alpha50 的 alpha 码 c_a 给出 `a_out ∈ Q(c_a)`，故

```
o ∈ [ 2·min Q(c_a) − 1 , 2·max Q(c_a) − 1 ]
```

实测如 A2：alpha 码 217 → o ∈ [0.698, 0.706]，声明 0.70 落在其中；B2 与 B4 同码 223
→ 同一区间 [0.745, 0.753]，量化层面同样无法区分。

## 5. 交付物与复算方法

目录 `deliverables/forensics/`：

```
plates/                     128 份候选源稿 JSON（候选×背景，每背景一个稿本）
renders/*.png               128 张由真实服务导出的 PNG
renders/montages/*-grid.png 6 张家族对照网格（行=候选，列=背景，首列琥珀框=原始单背景）
render-manifest.json        每张图的版面/稿本/artifact/双摘要/源稿路径（可追溯性）
forensic-results.json       实测码、同/异分组、量化区间反演（机读）
appendix-tables.md          由实测结果自动生成的码表与区间表
analysis/                   全部仅用 Python 标准库的可复算脚本
  model.py                  逐字转写 paint.go 的线性光/预乘/量化模型
  pngio.py / pngwrite.py    标准库 PNG 读/写
  recipes.py                候选家族与背景的最终参数（合法棱版输入）
  render_service.py         仅经现有 HTTP 契约建稿、修订、渲染、取图
  analyze.py                读真实 PNG、与模型逐码核对、区间反演
  montage.py / _verify_montage.py  生成并严格逐点校验对照网格
  build_report.py           重新生成 appendix-tables.md
  reproduce.sh              一键复算整条流水线
```

一键复算（需要 Go ≥ 1.24 构建既有服务；分析侧仅 Python 标准库）：

```sh
bash deliverables/forensics/analysis/reproduce.sh
```

复算会重新构建棱版二进制、在临时数据根启动真实 HTTP 服务、重渲 128 张 PNG、
重新做逐码核对（当前结果 128/128 与 `paint.go` 模型一致）、重建并校验 6 张网格、
重生成数据附录。脚本以 `python3 -I` 运行，不依赖工作目录中的任何模块。

### 给接收同事的最短操作流程

1. 在原图找到一块**满覆盖、平坦**的内点，记录其 RGBA 码与背景码。
2. 用同一图层定义在黑、白、一个彩色背景上各渲一张（棱版改 `background` 即可，
   走正常修订/渲染，不需要新接口）。
3. 若黑/白上出现 multiply→黑、screen→白的端点行为，据此定混合方式；否则按 §4 表
   判断当前观测能约束到复合量还是能拆出 o、s。
4. 需要覆盖度时，加一个 alpha=0.5 的背景，用 `o=2·a_out−1` 取 o 的量化区间。
5. 永远把结论表述为区间与“仍相容的候选集合”；若落在家族 B2/B4 或 D 这种结构歧义里，
   明确标注“像素观测不可唯一确定，需稿本/几何来源裁决”，不要给单点猜测。

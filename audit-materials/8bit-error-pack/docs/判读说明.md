# 8 位 PNG 自动比色判读说明（调用方版）

本包回答一个问题：**自动比色看到的像素差异，哪些只是 8 位输出容器的量化噪声，
哪些已经是设计稿或合成结果的真实变化？** 全部结论由本包内独立参考实现对
生产服务（未改动的 `prismplate`）真实 PNG 成品计算得出，可按
`README.md` 一键复算。

## 1. 生产管线与三个误差来源

生产渲染（`internal/raster` + `internal/paint`，本包未修改）对每个像素做：

1. **覆盖采样**：每像素 2×2 共 4 个固定中点采样，求平均覆盖率；
2. **颜色转换**：直通 sRGB 颜色经 IEC 61966-2-1 转到线性光，做预乘 alpha
   的 source-over（含 normal/multiply/screen）合成，输出前再转回 sRGB；
3. **8 位编码**：`math.Round(v*255)` 落到 0..255 整数码格，alpha=0 的像素
   RGB 强制清零。

三类误差由此分开，对应数据文件 `data/*.stages.json`。以主探针
`quant-probe` 的实测数量级为例（预乘线性光，全量像素）：

| 阶段 | 记号 | 度量空间 | 实测最大绝对差 | 性质 |
| --- | --- | --- | --- | --- |
| 覆盖采样 | E_coverage | 预乘线性光 | 约 2.2e-1（边界带），RMSE 约 8e-3 | 几何离散化，**不是**输出量化 |
| 颜色转换 | E_transfer | 预乘线性光 | 约 1e-16（机器 epsilon 量级） | binary64 浮点往返，比码格小 13 个数量级 |
| 8 位编码 | E_encoding | 预乘线性光 | 约 4e-3；叠底后 dE00 最大约 0.70 | 输出容器量化 |

独立参考实现与生产 PNG 的逐码对照记为 E_reference。除专门构造的半码 tie
探针外，全部稿逐像素零失配；tie 探针上两套独立实现的 libm `pow` 在半码
边界相差 1 ULP，导致恰好 1 码分歧（255 个半码边界中 38 个受影响，见
`data/tie-divergence.json`），仍在 1 码量化包络内。这说明应按**包络**而非
位级一致判读，也说明独立参照忠实复现了生产契约。

## 2. 可验证的误差界

以下界均由 `reference/bounds.py` 以穷举/闭式方式验证，不是经验估计：

1. **8 位码格界（单通道，sRGB 直通单位）**：四舍五入保证
   `|Δc| ≤ 1/510 ≈ 0.001961`，即至多半个码。alpha 通道同界。
2. **线性光码距不均匀**：解码后相邻码的线性光步长实测在亮端最大
   （码 254→255，约 0.00890；具体全部数值见
   `data/counterexamples.json` 的 `linear_step_widths`），最小非零步长
   约 0.000304，相差约 29 倍。因此**不要**把"半个码"折算成固定线性光
   容差；一个码在亮端与暗端的物理权重不同。
3. **直边覆盖界**：单条竖直/水平边在 2×2 网格下，覆盖率估计与精确面积
   之差 `≤ 1/4`（`sweep_edge_error` 穷举扫边验证）。曲线轮廓无此闭式界，
   只能用稠密网格估计，且估计器自身有残差——这是**不能外推的范围**之一。
4. **叠底后的界**：不透明底图上 source-over 在直通空间是凸组合
   `out = a·src + (1−a)·backdrop`，故叠底后单通道 sRGB 偏差
   `≤ a/510`。低透明像素的大 RGB 差被 alpha 因子压小，这就是下一节的根据。

## 3. 低透明像素：直通 RGB 差大，不代表叠底后差得多

`veil-demo` 稿在同一张中灰底上放了 alpha=0.002 的纯红与纯蓝两片薄纱。
两片的**直通 RGB 最大通道差为 1.0**（红 1,0,0 对蓝 0,0,1），但叠到同一
底图后：

- sRGB 最大通道差约 0.002（见 `data/counterexamples.json` 的 A 节）；
- CIEDE2000 色差小于 1 个 JND 量级；
- 实际生产 PNG 两区域叠底后码值差为 0 或 1 个码。

**判读规则**：

- 对 alpha < 1 的像素，禁止直接比较直通 RGB（更禁止对其计算 dE00——
  dE00 只对不透明颜色有定义）。
- 必须先把候选像素与**同一面不透明底图**做 source-over 摊平，再在摊平结果
  上度量。本包固定提供 dark/mid/light 三面底图，调用方应选择与实际成品
  承载面一致的底图；换底图会改变结论，不得用单一底图外推。
- alpha=0 像素的 RGB 在生产契约里被清零，其 RGB 差异**没有任何视觉意义**，
  比色时应整体跳过或只看 alpha。注意一个非对称细节（见
  `data/alpha-channel-facts.json`）：只有**浮点 alpha 恰为 0** 的像素才清零
  成 (0,0,0,0)；浮点 alpha>0 但取整后 alpha 码为 0 的像素仍保留 RGB 码
  （实测如 (230,51,38,0)）。这类像素解码后覆盖率为零，在任何不透明底图上
  视觉完全惰性，比色时同样应跳过其 RGB，不可据其非零 RGB 报差异。

## 4. 哪些差异是量化，哪些是真实变化

### 4.1 只属于输出量化（可接受，不需要改稿）

同时满足以下条件的差异归为量化：

1. 同一份稿本的两次渲染（生产成品对生产成品，或独立参考对生产成品）；
2. 差异像素处几何覆盖没有跨边（不在轮廓边界带内）；
3. 每通道码值差 ≤ 1，alpha 码值差 ≤ 1；
4. 摊平到约定底图后 dE00 不超过本包实测的量化包络
   （各稿数值见 `data/*.stages.json` 的 `post_composite` 段）。

### 4.2 已是设计/合成的真实变化（必须按变更处理）

`quant-probe` 的五个设计变体各改一个真实决策（硬边平移 0.5px、可见薄纱
色标改色、screen 换 multiply、组透明度 0.35→0.60、不透明面板 1/255 微
改色）。它们的生产 PNG 与基线相比（`counterexamples.json` 的 B、C、D 节）：

- 硬边平移、混合方式、组透明度、色标改色产生的受影响像素数与最大码值差
  都**显著超过** 1 个码的量化包络；
- 0.5px 硬边平移即产生越界反例：边界带像素出现多码差异，且叠底后
  dE00 最大值远超量化包络——**覆盖采样误差不属于输出量化**，1/4 的覆盖
  界与 1/510 的码格界是两个独立的界，不能互相借用；
- 混合方式或组透明度变化会在整片区域产生同向、成结构的差异，与量化的
  孤立、无方向性单码抖动形态不同；
- 但 1/255 微改色只产生 1 码差异，与量化不可由码距区分（见第 5 节），
  所以"是否同稿本"必须先由稿本身份判定，不能由像素反推。

### 4.3 确会越界的反例（不要外推的范围）

- **码格界不外推到几何**：编码界 1/510 只约束同一浮点像素的取整；硬边
  0.5px 移动立刻产生多码差异（B 节实测）。
- **直边界不外推到曲线**：1/4 覆盖界只对轴对齐直边成立；三次曲线
  （固定 24 段细分）与描边轮廓只能用稠密网格估计，估计器 4×4→8×8 的
  残差记录在各稿 `estimator_convergence_4_vs_8_linear`。
- **单底图结论不外推**：摊平色差是 (像素, 底图) 的二元函数；薄纱在深底
  与浅底上的 dE00 不同，换底图需重算。
- **浮点往返误差不外推为取整误差**：颜色转换的 binary64 残差
  （`data/controls.json`，50 位十进制参照）比码格量化小 2–3 个数量级，
  两者不能合并成一个容差。

## 5. 为什么不能靠统一放宽阈值

`counterexamples.json` D 节给出阈值陷阱的实测（含专门的微改色变体
`quant-probe-micro-tint`）：

- 同稿本量化的实测包络是每通道 1 码；
- 把不透明面板的源颜色改动 1/255 是**真实设计变更**，但渲染后 21744 个
  像素的码差恰好全为 1 码——与量化噪声在码值空间完全重叠；
- 因此任何"码差 ≤1 即判同稿"的全局阈值都会静默放过这类真实改色，而把
  阈值收紧到 0 又会把正常量化误报为变更。单一全局码值阈值在原理上不可分
  类，这不是调参能解决的问题。

正确做法是**分阶段、分区域、结合稿本身份**判读，而不是调大一个数：

1. 先比稿本哈希/结构，确认是否同一稿本（不同稿本不存在"只是量化"的
   前提）；
2. 同稿本比色：边界带用覆盖界 + 摊平度量，内部区用 1 码界 + 摊平 dE00；
3. 不同稿本：差异即设计/合成变化，按变更流程上报，即使它只有 1 码；
4. 低透明像素一律先摊平再度量，alpha=0 像素跳过 RGB。

## 6. 度量选择速查

| 问题 | 用什么 | 不要用什么 |
| --- | --- | --- |
| 8 位容器差多少 | 码值差（0..255） | dE00（对码格无定义优势） |
| 物理光强差多少 | 预乘线性光 RMSE/最大值 | 直通 sRGB 欧氏距 |
| 人眼能否分辨（不透明） | 摊平后 CIEDE2000 | 线性光数值差 |
| 低透明像素颜色 | 同底摊平后再算上述度量 | 直通 RGB 直比、对透明像素算 dE00 |
| 覆盖率是否变了 | 边界带定位 + 覆盖界 | 全局颜色阈值 |

## 7. 复算入口

```sh
python3 analysis/generate_sources.py            # 重建源稿
GO_BIN=<go> python3 analysis/fetch_production_pngs.py   # 生产真实 PNG
GO_BIN=<go> python3 analysis/tie_analysis.py     # 半码 tie 实现差清单
python3 analysis/run_study.py                   # 三段误差拆分
python3 analysis/build_controls.py              # 16 位对照 + 十进制转换参照
python3 analysis/alpha_channel_study.py         # RGBA alpha 取整与清零契约
python3 analysis/counterexamples.py             # 反例与阈值陷阱
python3 analysis/export_pixel_reference.py      # 逐像素数值谱系
python3 analysis/verify_pack.py                 # 一键校验，全部应 PASS
```

生产算法与生产阈值在整个过程中未被修改；本包是旁路证据，不参与渲染路径。

# 细缝随平移消失：排查结论与证据

对象：48×48 透明画布、单个 normal 图层（opacity=1）、单个 evenodd 填充、不透明蓝色实刷、
初始变换为单位阵的形状稿。外轮廓 `M(6,24) C[(6,6),(42,6),(42,24)] C[(42,42),(6,42),(6,24)] Z`，
内轮廓为 `(22.1,12)-(22.4,12)-(22.4,36)-(22.1,36)` 的闭合矩形。形状分别水平平移
0、0.25、0.5 px。

## 结论

**孔洞几何没有变化，变化的是 2×2 覆盖采样能否在某个平移位置"看见"孔洞。**

- 三次平移里，内轮廓的 4 个顶点、边长、面积（0.3 × 24 = 7.2 px²）完全一致；SVG 在每个
  平移位置都原样保留内轮廓路径，只有 `transform` 的平移分量不同。
- PNG 的 2×2 采样点在像素内固定位于 x = k+0.25 和 k+0.75（间距 0.5 px）。内轮廓在 x 方向
  只有 0.3 px 宽，**比采样间距还窄**，因此存在整段平移区间里没有任何采样列落进孔洞。
- 0.25 px 平移正落在盲区中间。该位置的 PNG 与"删掉内轮廓"的对照图**逐字节相同**——这不是
  孔洞消失，而是采样器完全没有采到它。
- 盲区在一个 1 px 周期内占 0.4 px（40%），成两段：`(0.15, 0.35]` 与 `(0.65, 0.85]`。

只检查 0、0.25、0.5 这三张图，恰好会看到"细缝出现→消失→再出现"，很容易误判成几何在
变化；真实情况是每隔一个 0.5 px 的采样相位才看得见一次。三张图里有两张落在可见相位、
一张落在盲区，属于对盲区的抽样太少，而不是对孔洞的证据。

**这不是渲染 bug，也不应被当成"小尺寸特征在低采样下必然失真"就算了。** 它是文档化的
2×2 采样契约与小于采样间距的特征之间的确定交互，会导致"PNG 与 SVG 不一致"的校样歧义。
作者侧应改用能覆盖相位的检查（见文末建议）。

## 几何证据（与像素无关，可先行排除"几何变化"）

1. **展开后的路径完全相同。** `internal/geom/geom.go:19` 的 `Flatten` 对 C 固定细分 24 段，
   与平移无关；SVG 输出的 `d=` 属性在三张图里逐字符相同，`samples/offset-*.svg` 里可见
   内轮廓 `M22.1 12L22.4 12L22.4 36L22.1 36Z`。三份 SVG 去掉 `transform` 后 `diff` 为空。
2. **变换只含平移。** 每份 SVG 的 `transform="matrix(1 0 0 1 <dx> 0)"`，线性部分恒为单位阵，
   不引入缩放/旋转，孔洞宽度始终 0.3 px。
3. **形状内部关系不变。** 内轮廓仍是外轮廓内的第二条闭合环，evenodd 下这必然形成洞；
   `internal/geom/geom.go:96` 的 evenodd 判定只看交点数奇偶，与平移无关。

## 像素证据（采样器确实会在盲区漏掉孔洞）

采样栅格（`internal/raster/raster.go:26`）：每个像素 4 个样本，
`x + (sx+0.5)/2` 即 k+0.25 / k+0.75。内轮廓 x 范围为 [22.1+dx, 22.4+dx)，宽度 0.3 px，
所以只有 22.25 / 22.75 / 23.25 这几列样本可能落入。

| dx | 落入孔洞的样本列 | 解析可见 | 该位置"被孔洞压暗"的像素数 | 与无洞对照图像素差 |
|---|---|---|---|---|
| 0 | 22.25 | 是 | 24（列 22，α=128） | 24 px |
| 0.25 | 无 | 否 | 0 | 0（**文件逐字节相同**） |
| 0.5 | 22.75 | 是 | 24（列 22，α=128） | 24 px |

- 三张 PNG 都与独立 Python 复刻实现（`analyze.py` 的 `render_png_pixels`，含 sRGB→线性光→
  预乘合成→RGBA8 舍入）逐像素一致，`png_matches_mirror=true`，因此样本文件本身可信。
- 0.25 位置的 PNG 与其"无内轮廓"对照 **sha256 相同**（`7474744e…`）；0 和 0.5 位置各有 24 个
  像素与对照不同，且差异全部是 α 255→128，位置正是孔洞列 22、行 12–35。这排除了"孔洞挪到
  了别处"——如果几何变了，差分会出现在别的列或形状不同；这里只可能是"没被采到"。
- 部分像素 α<255 的像素数在三张图里分别是 84 / 68 / 98，这不是孔洞可见性指标：外轮廓边缘
  抗锯齿也产生部分覆盖。必须用"四样本全在外轮廓内、且至少一样本在内轮廓内"的判据
  （`analyze.hole_pixels`、`detect_hole.py`）才能把孔洞与轮廓抗锯齿分开。

## 盲区盘点（0 ≤ dx < 1）

闭式模型（`analyze.lattice_model`）：
样本列 c 命中孔洞 ⇔ `22.1 ≤ c − dx < 22.4`。由此：

- 命中区间：dx ∈ (c−22.4, c−22.1]。三列分别为 (−0.15, 0.15]、(0.35, 0.65]、(0.85, 1.05]，
  与 [0, 1) 取交后是 [0, 0.15]、(0.35, 0.65]、[0.85, 1)。
- **盲区：`(0.15, 0.35]` 与 `(0.65, 0.85]`，合计 0.4 px，占 40%。**
- 端点由 `geom.Path.Contains` 的半开判定决定：左边缘（样本恰在 22.1+dx 上）算内，右边缘
  （恰在 22.4+dx 上）算外。0.15 与 0.65 落在可见端，0.35 与 0.85 落在盲端。

生产路径上的稠密扫描（`sweep`，步长 0.001，直接在 `validate.Compile + raster.Render` 上跑
1001 个平移）给出相同区间（`sweep.json` 的 `spans`）：

```
visible [0, 0.150]   hidden [0.151, 0.350]   visible [0.351, 0.649]
hidden [0.650, 0.850]   visible [0.851, 1.000]
```

真实 HTTP 服务上以 0.05 步长重跑（`verify_service.py` → `http-sweep.json`）得到：
可见 0.00–0.15、盲 0.20–0.35、可见 0.40–0.65、盲 0.70–0.85、可见 0.90–0.95；
每一步都满足 `png_matches_mirror=true`、`svg_keeps_inner_contour=true`。与闭式模型
在全部 1001 个 0.001 步长平移上对照，`sweep.json` 无一例不符。

**只检查 0、0.25、0.5 三张图会漏掉的位置：**

- 整个 `(0.15, 0.35]` 区间：0.16–0.34 任何平移都会得到"看不见洞"的 PNG，0.25 只是其中一个样本。
- 整个 `(0.65, 0.85]` 区间：0.66–0.84 同样看不见；三张图里完全没有覆盖这一段。
- 0.251–0.349 与 0.751–0.849 这些"离可见只差一点点"的位置，三张图也无法区分。
- 反过来，三张图也没覆盖 0.35 / 0.65 这两个半开端点：它们属于盲区，但按"平移 0.25 后
  看缝消失"的直觉很容易被误以为应该可见。

如果只按"0 可见、0.25 不可见、0.5 可见"外推，还会错误地以为周期是 0.5 px 且盲区只有
一点；实际盲区宽度是采样间距的 0.4 倍，且相位边界由半开区间决定。

## 证据的可复现性

所有证据均在本仓库内，只用标准库；需要 Go 1.24+ 构建服务。

```
# 1) 纯几何 + 独立像素复刻 + 已存 PNG 校验（不需要起服务）
python3 analysis/seam-study/analyze.py --verify

# 2) 闭式盲区模型与逐 0.01 px 的可见性表
python3 analysis/seam-study/lattice.py

# 3) 生产路径稠密扫描（validate+raster，1001 个平移），生成 sweep.json
go run ./analysis/seam-study/sweep -step 0.001 -out analysis/seam-study/sweep.json

# 4) 真实 HTTP 服务重跑（含无洞对照与 SVG 检查），生成 samples/ 与 http-sweep.json
go build -o /tmp/prismplate ./cmd/prismplate
python3 analysis/seam-study/run_service.py --binary /tmp/prismplate --keep /tmp/seam-data
python3 analysis/seam-study/verify_service.py --binary /tmp/prismplate --step 0.05

# 5) 对单张 PNG 做"孔洞像素"判定
python3 analysis/seam-study/detect_hole.py analysis/seam-study/samples/offset-0.25.png
```

`run_service.py` 与 `verify_service.py` 使用固定的版面 id，请总是传一次性 `--keep` 数据根，
不要指向长期数据。`sweep.json` 与 `http-sweep.json` 已提交，可直接对照，无需重跑。

文件清单：

| 路径 | 作用 |
|---|---|
| `gen_scenes.py` | 生成 0/0.25/0.5 的稿本 JSON，以及同位置的"无内轮廓"对照稿本 |
| `run_service.py` | 起真实服务、提交稿本、保存 PNG/SVG 与回执 |
| `verify_service.py` | HTTP 级稠密平移扫描，逐张校验像素与 SVG |
| `analyze.py` | 几何闭式模型 + 独立 PNG 复刻 + 孔洞判据 + 对照比对 |

| `samples/` | 三组 PNG/SVG 与 `responses-*.json`（含无洞对照） |
| `sweep.json` | 1001 个平移的孔洞像素统计与可见/盲区区间 |
| `http-sweep.json` | 0.05 步长的 HTTP 实测结果与区间 |

## 给作者的临时建议（不改服务）

1. **不要用单张 PNG 判断窄特征是否存在。** 对宽度小于 0.5 px 的镂空/细线，至少按 0.05 px
   步长平移取样，或多相位各出一张，再判断。可直接复用 `verify_service.py` 的扫描思路。
2. **用本文的判据看孔洞，而不是看"有没有半透明像素"。** 外轮廓抗锯齿同样产生 α<255；
   判据是"四个子样本全在外轮廓内、且至少一个在内轮廓内"（`detect_hole.py`）。
3. **交付前以 SVG 复核内轮廓是否仍在。** 本例 SVG 在三个位置都保留内轮廓，可作为几何未变的
   交叉证据；但不要把 SVG 当像素校样，README 已说明两者覆盖率可能不同。
4. **需要孔洞在任意平移都稳定可见时，临时改稿而不是改渲染器：**
   - 把内轮廓放宽到 ≥ 0.5 px（例如 x 从 22.1–22.4 改为 22.0–22.6），或
   - 让外轮廓与内轮廓的边界落在 0.5 px 的整数倍上（例如 22.0、22.5），使采样相位对齐，或
   - 以更高分辨率导出（画布上限 512×512），再按比例缩小检查；这能减小但不会消除相位依赖。

   若要根本解决，需要在渲染契约层面增加采样率或做覆盖率解析积分，那属于产品变更，超出本次
   排查范围。

## 边界说明

- 本仓库当前没有自动化测试套件（`go test ./...` 无测试文件），本目录是独立分析材料，不改
  动产品代码，也没有新增测试命令。
- `samples/` 中的文件由真实 HTTP 服务生成；`analyze.py --verify` 会从稿本重新推导每个字节
  并与磁盘文件比对，因此这些样本可被独立审计。
- 数值结论只对这一组几何（0.3 px 宽、24 px 高的内轮廓、2×2 采样、x 方向平移）严格成立；
  其它宽度/方向需按 `lattice.py` 的模型重算。
